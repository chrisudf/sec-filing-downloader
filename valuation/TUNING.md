# v2 语义阈值清单 —— 被拒绝时该调哪里

> 覆盖 `semantics_version=2`（2026-07-22）引入的全部可调阈值。
> 数据层（税则/货币/期间窗口/Q4 推导）的旋钮不在这里，见 review 包的 `TUNING.md`。
> 每项标注：**现值 / 代码位置 / 作用 / 什么信号出现时该调**。

## 校准证据（动手改之前先看这个）

这批阈值不是拍脑袋定的，落地时做过一次判别力实测：

| 输入 | 结果 |
|---|---|
| review 的 8 份样例假设（AAPL/ASML/CRCL/GOOG/MU/NVDA/SOFI/TSM） | **全部通过**（NVDA/AAPL 为含反双重计数的完整校验） |
| 2026-07-22 一次真实 sonnet 判断层跑出的 NVDA config | **被拦**——bear 盈利收缩至 base 的 47%，pe 又低于 base 的 0.6 倍 |

含义：**规则集通过了人工精修的参考假设，专门逮住机器采样漂移出来的那一份。**
所以看到拒绝时，**默认先怀疑假设，而不是先怀疑阈值**——8/8 的参考集都过了，
你这次过不了，多半是判断层真的给了自相矛盾的组合。确认假设有据可依之后再动下面的数字。

## 一、判断层被拒绝时（`app/valuation_service.py::_validate_judgment`）

报错信息会直接引用这些边界，按报错文案对号入座：

| 报错关键词 | 现值 | 位置 | 什么时候调 |
|---|---|---|---|
| `pe 需在 [8, 60]` | 下限 8（声明 `permanent_impairment` 放宽至 4），上限 60 | :148 | 深度周期股的真谷底（内存/航运）确实会顶到 8；但**正确做法通常是声明永久受损或抬高 bear.pe**，而不是降下限。上限 60 在超高成长标的上可能不够，看到 bull 反复撞 60 再放 |
| `m1/m2 需在 [0, 60]` | [0, 60] | :151 | 同上；m2=0 表示"无次分部"，是合法值 |
| `g/g0 需在 (-0.35, 0.9)` | (-0.35, 0.9) | :154 | 极端复苏年（低基数反弹 >90%）会撞上限——先确认不是把一次性因素当成常态 |
| `gN 需在 (0, 0.12]` | (0, 0.12] | :156 | **终年增速必须为正**是刻意的：衰退终态应该建模进 margins 路径，不是负 gN（负 gN 会让 DCF 十年段自相矛盾）。不建议放松 |
| `margins 必须是 (-0.3, X)` | 下界 -0.3；上界 `max(0.65, min(0.9, 1.2×TTM FCF率))` 动态 | :136 | 上界已随标的自适应（特许权类高 FCF 率公司不会被"维持现状"路径卡住）。撞上界说明假设的 FCF 率比当前还高 20%+，要有依据 |
| `wacc 越界` | [0.05, 0.2] | :140 | 高利率环境或高风险标的可放宽上限 |
| `wacc-tg 需 >= 0.045` | 0.045 | :142 | **不建议放松**，DCF 终值对此极敏感（差值趋零时终值爆炸） |
| `opm/tax 越界` | opm (0, 0.95)、tax [0, 0.5) | :144 | MU 这类周期顶部 OPM 能到 66%，0.95 留了足够余量 |
| `情景排序：X 必须 bear <= base <= bull` | g/opm/pe/m1/m2 | :162 | **不该调**。倒挂基本等于判断层写串了情景 |
| `bear 双重计数` | 触发条件：bear 盈利 < base 的 **80%** 且 pe/m1/m2 < base 的 **0.6 倍** | :177 | 这是压漂移的主力规则。真觉得误伤，优先用 `permanent_impairment=true` + `impairment_note`（要给财报原文出处）豁免单个情景，而不是放宽 0.6 |
| `bull 双重计数` | bull 盈利 > base 的 **125%** 且 pe/m1/m2 > base 的 **1.4 倍** | :183 | 同上；bull 没有豁免通道（景气顶点倍数收敛是稳健假设） |
| `margins 谷底 < 0.4×TTM FCF率` | 0.4 倍；仅当 TTM FCF 率 > 2% 时启用 | :191 | 比腰斩更深的常态化路径属于永久受损，同一豁免通道 |
| `fwd_shares 必须为正数` | > 0 | :107 | 不该调 |

**豁免通道**：在单个情景里设 `"permanent_impairment": true` + `"impairment_note": "<财报原文出处>"`，
可解锁 pe 下限（8→4）、反双重计数（bear 侧）、margins 谷底三项。设计意图是
"永久受损时低盈利×低倍数自洽"——所以它要求出处，且会被记录进报告。

## 二、引擎红旗（`valuation/engine.py`）—— 不拒绝，但会打回判断层一次并显示在摘要

red 级会触发一次经济复审（打回判断层重出假设）；复审后仍越界就带红旗出报告。
yellow 级只在摘要红旗区展示。**红旗不阻断出报告，但会阻断连续性锚的持久化**（见下节）。

| 红旗 | 级别 | 现值 | 位置 | 什么时候调 |
|---|---|---|---|---|
| SOTP 降级线 | — | `seg1_share >= 0.85` 时 SOTP 不入综合 | :171 | 0.85 以上时 SOTP 与 PE 法实为同一笔盈利乘两次倍数。真双分部标的（分部真能分拆估值）若被误降级，可提到 0.9 |
| DCF 第 10 年营收 > 8×TTM | 🔴 red | 8 倍（≈10 年 CAGR 23%） | :211 | 超高成长标的的 bull 情景会稳定触发（NVDA bull 实测 13.3×）。这是**提醒不是错误**——若你认可该增长路径，让它带红旗出报告即可 |
| 终值折现占 EV > 75% | 🔴 red | 0.75 | :214 | 长久期成长股常触发；调高等于放弃这个警示，不建议 |
| 隐含 P/TTM FCF 界外 [5, 90] | 🔴 red | [5, 90]，仅当 FCF 基准 > 营收的 2% | :217/:220 | 分母在 `ttm_revenue_override` 场景已按利润率换算（避免陈旧 XBRL 造假红旗）。低 FCF 或亏损标的自动跳过 |
| 综合隐含 P/调整后净利 界外 [6, 60] | 🟡 yellow | [6, 60] | :226 | 纯展示 |
| 方法离散度 > 2x | 🟡 yellow | 2.0 | :228 | CRCL 实测 2.08x。离散大时综合目标价可信度低，应分法看 |
| base 综合偏离现价 > ±35% | 🟡 yellow | 0.35 | :243 | 估值可以偏离市价，但要显式辩护。你若长期做深度价投，可放宽到 50% |

## 三、连续性（默认开启）

| 旋钮 | 现值 | 位置 | 说明 |
|---|---|---|---|
| 锚存放位置 | `prev_configs/{ticker}.json`（已 gitignore） | — | 不能放 `jobs/`——那里按 mtime 3 天清理，锚活不过一个季度 |
| 持久化条件 | **仅 gate-clean**（无 red 红旗）且 standard 模式 | — | 带病假设冻结成锚会让偏差跨运行复利。这是"方差可见、偏差不可见"的防线 |
| 失效：语义版本 | `semantics_version != 2` | — | v1 倍数假设在 v2 联动约束下不可复用 |
| 失效：新报告期 | `manifest_latest` 变化 | — | **最重要的一条**——财报后按构造低反应是连续性最危险的失效模式 |
| 失效：价格变动 | `> 15%` | — | 市场环境已变，倍数/wacc 需重估。波动大的标的觉得太频繁可提到 25% |
| 整体关闭 | `VALUATION_NO_CONTINUITY=1` | — | 想看"无锚定"的原始采样时用 |
| 显式指定基准 | `VALUATION_PREV_CONFIG=<path>` | — | 优先级高于自动锚；指向 bundle 里的 `config_假设留档.json` |

## 四、模型与调用预算

| 旋钮 | 现值 | 位置 | 什么时候调 |
|---|---|---|---|
| `VALUATION_MODEL` | **opus**（v2 起的默认） | :288 | sonnet 同输入 4 次采样 base 全距 25.7%，opus CV≈3.5%。判断层是全链智力瓶颈，不建议为省额度换回；赶时间可临时 `VALUATION_MODEL=sonnet` |
| `CLAUDE_TIMEOUT` | 600s | :40 | opus 在 ~45k 字符 prompt 上更慢。超时会让整个任务报废 |
| 单次运行总调用 | ≤ 3（首次 + schema retry 1 + 经济复审 1） | — | 刻意不做"拒绝就重采样"的循环——硬 gate 循环会教模型贴边过关，制造边界聚集偏差 |
| 章节预算 | 45k 总量，按文件平分；fact 通道优先于 risk | `extract_sections.py` | 判断层 notes 反复说"摘录未含 XX"时加预算（代价=更长 prompt）。极端关键词密集的文档理论上会把 risk 通道挤空，真实 NVDA 10-K/10-Q 实测 risk 仍拿到 3+4 条 |

## 五、排错顺序建议

1. **先看拒绝信息指向哪个情景的哪个字段**——v2 的报错都带具体数字（"收缩至 47%"），
   直接告诉你判断层给了什么组合。
2. **判断这是不是真的自相矛盾**。bear 盈利腰斩又给谷底 PE，多半是判断层把周期算了两遍；
   若你确信是永久受损，走 `permanent_impairment` 豁免（要出处），别改阈值。
3. **确实是阈值太紧再改**，改完**跑一遍回归**：8 份样例 config 应该继续全过，
   否则说明放得太松。回归脚本是 `valuation/check_configs.py`（用法在文件头），
   指向一个装着 `*_config.json` 的目录即可：

   ```
   .venv\Scripts\python valuation\check_configs.py <配置目录>
   ```
4. 阈值改动记得同步到 `judgment_prompt.md` 的「引擎机制」段——
   那里向模型公开了这些规则，**规则和公开值不一致会让模型浪费 retry 试探**。
